# AlexClubs Selective — пользовательские обновляемые списки

**VPN только для выбранных сервисов; всё остальное DIRECT.** Это отдельный профиль маршрутизации. Для подписки AlexClubs доступна доставка версий через стандартный заголовок Happ; ручной импорт также сохранён.

## Установить один раз

1. Открыть в Safari/браузере [IMPORT-HAPP.txt](https://raw.githubusercontent.com/Alesnyt/vpn_rules/happ-data/IMPORT-HAPP.txt).
2. На странице выбрать и скопировать **всё содержимое файла**, начинающееся с `happ://routing/add/`. Не копировать HTTPS-адрес из адресной строки: это вызовет ошибку разбора.
3. В Happ добавить маршрутизацию из буфера обмена. Выбрать свою подписку AlexClubs, если приложение спрашивает, к каким серверам применять правила. Это только локальная привязка внутри Happ, а не управление со стороны сервера.
4. Выбрать новый профиль **AlexClubs Selective**. Предыдущий **AlexClubs Selective v1** — старый статичный вариант; его больше не использовать для обновлений. Удалять серверы/подписку не надо.
5. Проверить **Global Proxy = OFF**, порядок правил **Block → Direct → Proxy**, затем переподключить VPN.

Профиль содержит постоянные ссылки на GeoSite/GeoIP вместо встроенного перечня доменов/IP. При дальнейших изменениях этих списков импорт повторять не нужно.

## Как обновляется

- Владелец редактирует только [vpn_rules.conf](https://github.com/Alesnyt/vpn_rules/blob/main/vpn_rules.conf) в ветке `main`, как для Shadowrocket.
- После сохранения GitHub Actions запускает сборку, актуализирует ASN-префиксы из RIPEstat и выполняет проверки. Результат публикуется одним коммитом в ветку `happ-data`.
- Happ загружает файлы по сохранённым адресам при обновлении геофайлов. Автообновление и его периодичность контролирует приложение на устройстве; публикация в GitHub не является мгновенной push-командой телефону.
- Для немедленной проверки есть кнопки обновления рядом с **geosite** и **geoip** в профиле. После загрузки нужно переподключиться, чтобы активное соединение использовало новые данные.
- Если сборка или получение ASN не удались, опубликованная ветка не меняется: последняя проверенная версия остаётся доступной. Проверять зелёный статус [Build Happ remote lists](https://github.com/Alesnyt/vpn_rules/actions/workflows/happ-lists.yml).
- Вариант ручного запуска сборки без изменения правил: Actions → Build Happ remote lists → Run workflow. Сборки по расписанию не настраивались; ASN актуализируются при сборке.

Постоянные адреса:

- [geosite.dat — домены](https://raw.githubusercontent.com/Alesnyt/vpn_rules/happ-data/geosite.dat)
- [geoip.dat — IP-сети](https://raw.githubusercontent.com/Alesnyt/vpn_rules/happ-data/geoip.dat)
- [rules.json — читаемые списки](https://raw.githubusercontent.com/Alesnyt/vpn_rules/happ-data/rules.json)
- [manifest.json — исходный коммит, состав и контрольные суммы](https://raw.githubusercontent.com/Alesnyt/vpn_rules/happ-data/manifest.json)

Эти файлы не являются VPN-подписками и не содержат UUID, паролей или секретных ссылок. По ним нельзя получить доступ к VPN.

## Автообновление через подписку AlexClubs

1. На мастере FR в настройке Happ Routing указать источник `https://raw.githubusercontent.com/Alesnyt/vpn_rules/happ-data/SUBSCRIPTION-HAPP.txt`. Панель 3X-UI получает его в фоне и сохраняет последнее проверенное значение при недоступности GitHub. В ответ подписки передаётся заголовок `Routing`; исходные VLESS-подключения не меняются.
2. На iPhone: главная → **⋯ у alexclubs.com → Настройки**. Включить **Авто обновления** и **Обновить при открытии**. Интервал AlexClubs — 12 часов. Он относится к подписке; iOS может отложить задачу, поэтому важен также запуск приложения.
3. **⋯ у alexclubs.com → Маршрутизация**: выбран AlexClubs Selective, маршрутизация включена, **Игнорировать импорт маршрутизации** выключено. Для отключения доставки можно включить игнорирование импорта; текущие локальные правила при этом остаются на устройстве.
4. GitHub создаёт SUBSCRIPTION-HAPP.txt с теми же правилами профиля и `LastUpdated` — Unix-временем исходного коммита сборки. На следующем обновлении подписки новая версия инициирует загрузку обоих геофайлов, даже если их URL не менялись. Повторная выдача той же версии не должна создавать бесконечную перезагрузку файлов.
5. Проверка без ручных кнопок GeoSite/GeoIP: открыть Happ после получения новой версии, дождаться завершения загрузки, затем открыть профиль и сверить «Последнее обновление» у обоих файлов. Изменения маршрутизации ядро применяет после переподключения; постоянный фоновый опрос ядром не настраивается.

SUBSCRIPTION-HAPP.txt использует `happ://routing/add/`, не `onadd`, с прежним именем профиля. От ручного IMPORT-HAPP.txt он отличается только меткой версии. DNS, Global Proxy OFF, FakeDNS OFF, AsIs и состав категорий сохраняются. Изменять DNS/базовую логику этой доставкой без отдельного согласования не следует.

Если автоматическое обновление не срабатывает: проверить переключатели подписки и игнорирования импорта, дату у файлов на телефоне, успешный статус Actions и `subscription_profile_version` манифеста; затем наличие заголовка Routing в ответе подписки. Не публиковать полную ссылку подписки, UUID или тело VLESS-выдачи. Если GitHub недоступен, сохранять последние исправные правила; не заменять их пустым значением. Ручное обновление геофайлов остаётся способом диагностики.

## Пользователь сохраняет управление

Пользователь сам выбирает этот профиль и может отключить маршрутизацию либо переключиться на другой профиль. После смены настройки необходимо переподключиться. Отключение селективной маршрутизации **не равно отключению VPN** — дальнейшее поведение определяется обычными настройками Happ.

Используется добровольный импорт `routing/add`, не `routing/onadd`. Первый профиль Happ может активировать автоматически после успешной загрузки; пользователь может сразу выключить его. Подписка может передавать тот же `routing/add` с новой версией; `routing/onadd` не используется.

Удаление пользовательского профиля прекращает его применение. Отдельный JSON-сервер/JSON-подписка может иметь ограничения Happ; этот комплект рассчитан на обычную VLESS-подписку AlexClubs.

## Что наследуется из Shadowrocket

- Сохраняются выбранные домены/IP, в том числе Apple, Telegram, YouTube, AI, GitHub, широкая зона `.ai` и ключевые слова, уже включённые владельцем в исходник.
- Поздние DIRECT-правила и GEOIP RU заменены DIRECT по умолчанию. Более ранние VPN-исключения сохраняются. Не добавляется общий список всех иностранных/заблокированных ресурсов.
- ASN преобразуются в наблюдаемые RIPEstat BGP-префиксы. Это снимок, а не точный эквивалент динамической ASN-базы Shadowrocket.
- DNS остаётся Google DoH и Quad9 без фильтрации, FakeDNS OFF, AsIs. Cloudflare DNS в профиле нет. `system DNS` из Shadowrocket не переносится буквально.
- Изменение доменов/IP доставляется внешними списками. Изменение **DNS, режима DIRECT по умолчанию, тегов или адресов самих файлов** требует новой версии оболочки профиля и отдельного пользовательского импорта; это не скрытое удалённое управление настройками.
- `api.ipify.org` вне VPN-списка: IP обычного провайдера на нём ожидаем. Проверять проксируемый трафик на сервисах из списка.
- DIRECT за границей означает интернет страны пребывания, не российский IP.

## DNS и широкие правила Google

Happ сохраняет существующие точные DIRECT-исключения для своих резолверов:

| Домен, только точное совпадение | IP, только один адрес | Маршрут |
|---|---|---|
| `dns.google` | `8.8.8.8/32` | DIRECT |
| `dns10.quad9.net` | `9.9.9.10/32` | DIRECT |

Это постоянные служебные исключения Happ, а не изменение исходного `vpn_rules.conf` для Shadowrocket. При преобразовании широких PROXY-правил ASN конвертер вычитает только эти два IP из полученных сетей. Родительский домен `google` не отменяет точное DNS-исключение; остальные Google-домены, соседние IP и IPv6-префиксы сохраняют PROXY. Общие DIRECT/PROXY-конфликты, явное противоречащее правило для самого DNS и неизвестный синтаксис по-прежнему останавливают сборку.

Google DoH, Quad9, `DnsHosts`, Global Proxy OFF, FakeDNS OFF, AsIs, порядок Block → Direct → Proxy и постоянные URL геофайлов сохранены. `profile.json` и `IMPORT-HAPP.txt` должны побайтно совпадать с предыдущей опубликованной версией: повторный импорт действующего **AlexClubs Selective** не требуется. Старый статичный v1 необходимо один раз заменить обновляемым профилем по инструкции выше.

Если сборка снова падает, открыть журнал первого неудачного шага Actions. При `Ambiguous Direct/Proxy IP overlap` или `Policy changed for ...` сопоставить точный адрес с исходником и `dns_bootstrap_direct` в манифесте. Не отключать проверку конфликтов и не переводить всю сеть Google в DIRECT. После исправления проверить зелёный статус, соответствие `source_commit` актуальному `main` и контрольные суммы всех файлов манифеста. Затем на устройстве обновить оба геофайла и переподключиться.

## Проверки и обслуживание

Проверено 08.09.2026:

- Первая [сборка GitHub Actions](https://github.com/Alesnyt/vpn_rules/actions/runs/34200299779) завершилась успешно и создала ветку `happ-data`.
- 19 автоматических тестов, независимое декодирование protobuf и загрузка в Xray 26.7.28 прошли. HTTPS-файлы совпали с контрольными суммами опубликованного манифеста.
- Happ 5.7.0 на Mac импортировал **AlexClubs Selective**, загрузил GeoSite 2,92 КБ и GeoIP 0,51 КБ с новых URL; повторная загрузка обоих файлов прошла без повторного импорта. В списке категорий распознаны `alexclubs-direct` и `alexclubs-proxy`; Global Proxy OFF, порядок Block → Direct → Proxy.
- Изменение состава списка без изменения импортируемого профиля проверено автоматическим тестом добавления/удаления домена. Фоновый таймер iOS/Android и фактический VPN-трафик на телефоне в этой проверке не наблюдались. VPN на Mac не включался.

Локально: `python3 happ/test_profile.py`, `python3 happ/test_remote.py`. Актуальная сборка: `python3 happ/remote.py --refresh-asn --output happ/dist`; затем `python3 happ/test_remote.py --artifacts happ/dist`. Запуск без `--refresh-asn` использует старый фиксированный ASN-снимок из тестов v1: он не содержит AS15169 и не подходит для текущего исходника. Опубликованный актуальный снимок доступен в `happ-data/asn-prefixes.json`; старые тестовые данные v1 намеренно сохранены для проверки совместимости.

Данные проверяются независимым protobuf-декодером, тестами добавления/удаления правил без смены профиля и проверкой загрузки в Xray. Неоднозначные изменения приоритетов и неизвестные конструкции остановят сборку для ручного разбора.

На телефоне перед раздачей проверить 443 с доменом, Telegram с медиа, YouTube и один AI-сервис, а также банк/Яндекс напрямую. Фоновую периодичность обновления нужно проверять в конкретной версии Happ; серверный push здесь не используется.

Исходный Shadowrocket-файл и старый статичный профиль сохранены. Для отката списка отменить ошибочное изменение исходника обычным revert-коммитом и дождаться успешной пересборки. Вручную ветку `happ-data` не редактировать.

Документация: [Happ](https://www.happ.su/main/ru/dev-docs/routing), [формат Xray](https://github.com/XTLS/Xray-core/blob/main/common/geodata/geodat.proto).
