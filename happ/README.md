# AlexClubs Selective v1 — Happ

> Это старый статичный профиль. Вместо него используйте [AlexClubs Selective с внешними обновляемыми списками](REMOTE.md). Обновления не встраиваются в VPN-подписку; выбор остаётся у пользователя.

Профиль маршрутизации, основанный на `vpn_rules.conf` из этого репозитория. Дата первой сборки: 08.09.2026. **Проверен импорт на Mac; фактический VPN-трафик на iPhone/Android ещё не проверен.**

## Добавить / обновить

1. Открыть [постоянную ссылку IMPORT-HAPP.txt](https://raw.githubusercontent.com/Alesnyt/vpn_rules/main/happ/IMPORT-HAPP.txt).
2. Скопировать всю одну строку, начинающуюся с `happ://routing/add/`.
3. В Happ выбрать добавление из буфера обмена. Если приложение спрашивает подписку, выбрать **свою подписку AlexClubs**, а не коммерческий VPN или отдельный пустой Server-List.
4. В настройках маршрутизации этой подписки выбрать **AlexClubs Selective v1**. Проверить: **Global Proxy выключен**, список Proxy не пустой.
5. Переподключить VPN. Существующие серверы, адрес, SNI и проверку TLS не менять.

Не добавлять HTTPS-адрес этого файла как подписку на VPN-серверы: он содержит только правила. [JSON](https://raw.githubusercontent.com/Alesnyt/vpn_rules/main/happ/AlexClubs-Selective-v1.json) также не является полным серверным профилем Xray.

В Happ профиль привязан к конкретной подписке. Импорт нового содержимого **с тем же именем** обновляет его вместо создания дубликата. Не менять имя при обычном обновлении правил.

## Как устроены обновления

- GitHub хранит последнюю опубликованную версию по постоянному HTTPS-адресу. История коммитов позволяет откатить изменения.
- `happ://routing/add/...` содержит **снимок JSON**, а не адрес для фонового опроса. Для ручного обновления снова открыть свежий файл и повторить импорт.
- Документированный способ доставки обновлений вместе с VPN-подпиской: сервер подписок добавляет эту строку в тело своего ответа или HTTP-заголовок `routing`. Тогда обновление подписки доставляет новую версию правил в нужную подписку Happ.
- Эта серверная интеграция **пока не установлена**. Публикация в GitHub сама по себе её не включает. Вымышленных параметров `UpdateUrl`/`UpdateInterval` здесь нет.
- Приватные UUID, URL подписок, ключи и пароли в публичный репозиторий добавлять нельзя. Друзья продолжают использовать свои существующие подписки.

## Политика трафика

- **DIRECT по умолчанию**: банки, российские и любые другие неуказанные сервисы идут через обычный интернет устройства, не посещая RU-ноду.
- **PROXY только по списку**: 153 доменных правила и 23 объединённых IP-диапазона в первой сборке. При выбранном RU relay это маршрут RU → FR.
- Apple, Cursor, AI-сервисы, Telegram, YouTube, GitHub и остальные исключения взяты из исходника. Широкие `.ai`, ключевые слова `gopro`/`nicegram`, сети Apple уже присутствовали в нём, а не добавлены конвертером.
- Поздние правила DIRECT и GEOIP RU заменены DIRECT по умолчанию, чтобы не перекрыть более ранние PROXY-исключения при группировке правил Happ.
- `api.ipify.org` не включён в список PROXY. Если он доступен напрямую, IP обычного провайдера при включённом VPN — ожидаемый результат.
- За пределами РФ DIRECT означает интернет страны пребывания, а не российский IP.

## DNS и ограничения переноса

Google DoH (`dns.google`, `8.8.8.8`) и Quad9 без фильтрации (`dns10.quad9.net`, `9.9.9.10`). Cloudflare как клиентский DNS не используется. Адреса DNS добавлены в Direct и DnsHosts, домен RU-ноды — в Direct без фиксации IP.

Это не буквальный перенос `dns-server = system` из Shadowrocket. Используются `DomainStrategy = AsIs`, FakeDNS выключен. Применение правил к внутренним DNS-запросам зависит от Happ; холодный старт с доменным адресом нужно проверить на телефоне. Проверку TLS не отключать.

IP-ASN преобразованы в снимок видимых RIPEstat BGP-префиксов на 08.09.2026. Это не живая ASN-база и не точный эквивалент MaxMind; при обновлении их нужно актуализировать. GeoSite/GeoIP-категории не используются, но Happ может загружать свои стандартные геофайлы.

## Проверка перед раздачей

- 9 автоматических тестов: формат, декодирование ссылки, воспроизводимость, сравнение с исходником на 1471 доменном и 332 IP-примерах. Это модель маршрутизации, не проверка реального трафика.
- Импорт проверен в Happ 5.7.0 на Mac: имя, Global Proxy OFF, списки и DNS распознаны. VPN на Mac не включался.
- На одном iPhone проверить основной сервер 443 **с доменом** после переподключения на Wi-Fi и мобильной сети, Telegram с медиа/звонком, YouTube и AI-сервис.
- Проверить, что банк/Яндекс и ресурс вне списка идут в `direct`, а перечисленные сервисы — в `proxy`. Затем повторить на Android.
- При проблеме отключить только этот профиль маршрутизации у своей подписки и переподключиться. Подписку, серверы и учётные данные не удалять.

## Обслуживание

`reference-shadowrocket.conf`, `reference-metadata.json`, `asn-prefixes.json` фиксируют источники. `conversion-report.json` содержит допущения и отличия. Исходный `../vpn_rules.conf` не изменён.

Генератор `build_profile.py --refresh` получает свежие данные из GitHub/RIPE и выводит JSON-комплект файлов в stdout; сам ничего не публикует и не записывает. `--offline happ` пересобирает из сохранённых снимков. Проверка: `python3 happ/test_profile.py` из корня репозитория. После пересборки нужно сохранить весь комплект, запустить тесты, проверить изменения и опубликовать новый коммит. Автоматической синхронизации с изменениями Shadowrocket пока нет.
